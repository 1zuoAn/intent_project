# 意图识别缓存服务接口文档 (Intent Cache Service API)

**Base URL**: `http://localhost:8000` (请根据实际部署地址修改)

## 1. 保存缓存 (`/cache/save`)

将 Agent 执行成功的参数模板保存到向量数据库，以便后续复用。

* **Method**: `POST`
* **Content-Type**: `application/json`

### 请求体通用结构 (Common Request Body)

```json
{
  "query": "用户原始查询语句 (例如: 2024年夏季连衣裙)",
  "history": "对话历史摘要 (可选)",
  "preferred_entity": "偏好平台 (例如: 知衣, 抖音, 海外)",
  "agent_type": "枚举值: douyi | zhiyi | abroad",
  "route_key": "路由标识 (决定命中后调用哪个后端接口)",
  "final_json": {
      // 业务参数体 (根据下方不同场景填入不同结构)
  }
}

```

---

## 2. 场景详情与路由映射 (Route Key Mapping)

后端根据 `agent_type` 和 `route_key` 组合来决定复用参数时调用的目标接口。

### 场景 A: 抖衣 (Douyi) - 综合查数

* **Agent Type**: `douyi`
* **Route Key**: `douyi_goods_list`
* **目标后端 URL**: `/goods-zone-list` (对应工作流中: 抖衣商品接口5/6)
* **业务逻辑**: 用于全网商品查询、筛选、排序。

**`final_json` 保存示例**:

```json
{
  "params1": {
    "rootCategoryId": 20005,
    "categoryIdList": [20169],
    "minPrice": 5000,           // 单位: 分
    "maxPrice": 10000,
    "yearSeason": "2024年夏季",   // [关键] 必须保存，用于跨年校准
    "minFirstRecordDate": "2024-05-01", // [关键] 筛选上架时间
    "maxFirstRecordDate": "2024-08-01",
    "sortStartDate": "2024-05-01",      // [关键] 统计开始时间
    "sortEndDate": "2024-05-07",
    "sortField": "saleVolumeDaily",
    "hotProperties": [["风格:甜美"]],
    "isMonitorShop": 0
  },
  "params2": {
    "keyword": "连衣裙",
    "sortStartDate": "2024-05-01",
    "limit": 50
  }
}

```

---

### 场景 B: 知衣 (Zhiyi) - 全网选品 (普通搜)

* **Agent Type**: `zhiyi`
* **Route Key**: `zhiyi_general_search`
* **目标后端 URL**: `/v2-0-x/item/simple-item-list` (对应工作流中: 知衣商品库全部接口)
* **业务逻辑**: 用于知衣平台的普通关键词搜索或类目筛选，不涉及复杂榜单。

**`final_json` 保存示例**:

```json
{
  "params1": {
    "categoryIdList": ["5001"],
    "minVolume": 100,
    "startDate": "2024-01-01", // 统计开始时间
    "endDate": "2024-01-31",   // 统计结束时间
    "sortField": "sale_volume_desc",
    "limit": 6000
  },
  "params2": {} // 通常为空或兜底参数
}

```

---

### 场景 C: 知衣 (Zhiyi) - 热销/新品榜单

* **Agent Type**: `zhiyi`
* **Route Key**: `zhiyi_hot_list`
* **目标后端 URL**: `/v2-0-x/item/list` (对应工作流中: 知衣热销接口)
* **业务逻辑**: 用于查询特定时间段的热销榜、新品榜。注意时间参数可能是数组格式。

**`final_json` 保存示例**:

```json
{
  "params1": {
    "dateRange": ["2024-01-01", "2024-01-07"], // [关键] 数组格式时间
    "saleStartDate": "2024-01-01",             // 上架时间
    "saleEndDate": "2024-01-07",
    "type": "new",                             // 榜单类型: new(新品), hot(热销)
    "sortField": "sale_volume_desc"
  }
}

```

### 场景 D: 知衣 (Zhiyi) - 店铺详情

* **Agent Type**: `zhiyi`
* **Route Key**: `zhiyi_shop_detail`
* **目标后端 URL**: `/v2-0-x/item/shop/all-item-list` (对应工作流中: 知衣店铺详情全部商品接口)
* **业务逻辑**: 用户指定查询某家店铺（如 ZARA）内部的商品数据。此场景缓存会通过 Scope 校验拦截“全网搜”意图。

**`final_json` 保存示例**:

```json
{
  "params1": {
    "shopId": 12345678,        // [关键] 店铺ID，Scope校验的核心
    "keyword": "",
    "startDate": "2024-01-01",
    "endDate": "2024-01-31",
    "sortField": "sale_volume_desc"
  }
}

```

### 场景 E: 海外 (Abroad) - 文本搜索

* **Agent Type**: `abroad`
* **Route Key**: `abroad_text_search`
* **目标后端 URL**: `/app/overseas/goods/search` (对应工作流中: 海外商品搜索接口)
* **业务逻辑**: 海外平台的关键词文本搜索。

**`final_json` 保存示例**:

```json
{

    "keyword": "dress",
    "putOnSaleStartDate": "2024-01-01", // [关键] 海外特有上架时间字段

    "maxPrice": 50.0

  }
}

```


## 3. 检查缓存 (`/cache/check`)

该接口用于在用户发起查询时，快速检索向量数据库，判断是否存在可复用的“参数模板”。
系统会根据 **向量相似度 (Tier 1)** 和 **LLM 裁判 (Tier 2)** 双重机制来决定是否命中。

* **URL**: `/cache/check`
* **Method**: `POST`
* **Content-Type**: `application/json`

### 3.1 请求参数说明 (Request Parameters)

| 参数名 | 类型 | 必填 | 描述 | 示例值 |
| --- | --- | --- | --- | --- |
| **`query`** | String | **是** | 用户当前的自然语言查询输入。 | `"2025年夏季连衣裙销量排行"` |
| `preferred_entity` | String | 否 | 用户当前的偏好实体/平台。用于辅助向量检索缩小范围。 | `"抖音"`, `"知衣"`, `"海外"` |
| `history` | String | 否 | 对话历史摘要。如果传入，会参与向量计算，增加上下文匹配度。 | `"用户上一轮问了女装趋势..."` |

### 3.2 响应参数说明 (Response Parameters)

| 参数名 | 类型 | 描述 |
| --- | --- | --- |
| **`hit`** | Boolean | **核心状态位**。<br>

<br>• `true`: 命中缓存。请直接使用 `final_params` 调用 `route_key` 对应的接口。<br>

<br>• `false`: 未命中。请走原有的 LLM 解析流程。 |
| `route_key` | String | **路由标识** (仅 `hit=true` 时返回)。<br>

<br>指明了该参数属于哪个具体的业务接口（如店铺搜、全网搜、榜单搜）。后端需维护 `route_key` 到 `API URL` 的映射表。 |
| `final_params` | Object | **最终参数体** (仅 `hit=true` 时返回)。<br>

<br>这是经过**时间校准**（如将“去年夏季”修正为“今年夏季”）后的完整 JSON 参数，可直接作为 Body 发送给第三方接口。 |
| `agent_type` | String | 命中的 Agent 类型枚举值 (`douyi`, `zhiyi`, `abroad`)。 |
| `score` | Float | 向量检索的相似度得分 (0.0 ~ 1.0)。<br>

<br>• `>0.99`: Tier 1 (直接命中)<br>

<br>• `0.95~0.99`: Tier 2 (进入 LLM 裁判)<br>

<br>• `<0.95`: Tier 3 (直接丢弃) |
| `reason` | String | 命中或拒绝的具体技术原因（便于调试）。 |

---

### 3.3 响应示例 (Response Examples)

#### ✅ 场景一：成功命中 (Hit - Tier 1/Tier 2)

> **业务含义**：找到了相似的历史查询，且通过了时间校准。可以直接发起查数请求。

```json
{
  "hit": true,
  "agent_type": "douyi",
  "route_key": "douyi_goods_list",
  "score": 0.985,
  "reason": "Tier 2: Judge Approved",
  "final_params": {
    "params1": {
      "rootCategoryId": 20005,
      "yearSeason": "2025年夏季",       // [注意] 已自动从缓存的2024修正为2025
      "sortStartDate": "2025-05-01",    // [注意] 时间已更新
      "sortEndDate": "2025-05-31",
      "minPrice": 5000,
      "maxPrice": 10000,
      "hotProperties": [["风格:甜美"]]   // 复用了复杂的属性筛选
    },
    "params2": {
      "limit": 50
    }
  }
}

```

#### ❌ 场景二：语义拒绝 (Miss - Tier 2 Rejected)

> **业务含义**：向量很相似（比如都是搜连衣裙），但关键条件冲突（如用户搜“监控店铺”，缓存是“全网”）。LLM 裁判拒绝复用。

```json
{
  "hit": false,
  "agent_type": "douyi",
  "route_key": null,
  "final_params": null,
  "score": 0.942,
  "reason": "Tier 2: Judge Rejected"  // 裁判发现 Scope 或 关键属性不一致
}

```

#### ❌ 场景三：无相关缓存 (Miss - Tier 3 Low Similarity)

> **业务含义**：是一个全新的问题，向量库里没有相似记录。

```json
{
  "hit": false,
  "agent_type": null,
  "route_key": null,
  "final_params": null,
  "score": 0.653,
  "reason": "Tier 3: Low similarity (<0.95)"
}

```
